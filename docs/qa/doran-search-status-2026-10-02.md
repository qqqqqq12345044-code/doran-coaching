### 1.1 색인된 15개의 정체
홈 1, 언어 페이지 3, 상세 9(12개 중), `/magazine` 1, **지역 리프 1**(`/local/서울특별시/마포구/공덕동/영어회화`).
- 상세 12개 중 3개(`japanese/school`, `chinese/school`, `japanese/other`)는 색인 목록에 없다. 미색인 목록에 있는지는 확인하지 못했다.
- 지역 리프는 build 시 미리 만들어지는 공덕동 15개 중 **1개만** 색인됨. 지역 허브(시/도·시/군/구·동)는 **0개**.

### 1.2 색인 안 된 50개의 정체
확인한 앞 10개가 전부 매거진 글(`/magazine/...`)이고 "최종 크롤링: 해당사항 없음"이다. 총 50개는 사이트의 매거진 글 수(50)와 일치하고,
`rss.xml`이 51개(글 50 + 홈)를 발견했다 → **매거진 글 50개가 전부일 가능성이 높다(전체 50행 목록은 UI 한계로 끝까지 열람하지 못함).**

### 1.3 Sitemap 처리 상태 — 가장 중요한 발견
| Sitemap | 제출 | 마지막 읽음 | 상태 | 발견 페이지 |
|---|---|---|---|---|
| `/rss.xml` | 2026-09-16 | 2026-09-24 | 성공 | 51 |
| `/sitemap.xml`(인덱스) | 2026-09-07 | 2026-10-01 | "색인 처리 완료" | **0** |
| `/sitemap/0.xml` | 2026-10-02(이번 작업에서 추가 제출) | 2026-10-02 | **"가져올 수 없음"**(사유 표시 없음) | 0 |

- 인덱스 상세에서 **"읽은 사이트맵" 목록이 비어 있다** → Google은 `/sitemap.xml`이 가리키는 shard 4개를 **아직 하나도 읽지 않았다.**
  즉 sitemap에 있는 98,244개 중 Google이 sitemap으로 발견한 URL은 0개다.
- 코드/서버 쪽 원인은 찾지 못했다: Googlebot·모바일 Googlebot·Yeti UA로 요청 시 4개 shard 모두 200, `application/xml`,
  XML 유효, 모든 `<loc>`이 ASCII 퍼센트 인코딩된 https 절대 URL, robots Allow 전체.
- "가져올 수 없음"은 제출 직후 일시 상태일 수 있다(제출 약 1분 후 재조회에도 동일). **원인 단정 불가 — 24~48시간 뒤 재확인 필요.**

## 2. Naver Search Advisor — 확인 불가
- 이 세션의 브라우저 도구가 `searchadvisor.naver.com` 접근을 안전 제한으로 차단했다. 우회하지 않았다.
- 확인된 것(공개 정보): 인증 파일 `naver192558…html` Production 200, robots/sitemap 정상, IndexNow **HTTP 200**(아래 3장).
- 공개 Naver 검색 `site:dorancoaching.com` 결과에는 **홈(`/`)만** 보였다(`/local`·`/magazine` 질의는 0건).
  Naver `site:`는 참고 지표일 뿐이며 정확한 색인 수가 아니다.
- **Search Advisor 안에서 직접 봐야 하는 항목은 이 문서 마지막 "사용자 확인 목록" 참고.**
  "수집 주기 빠르게" 같은 옵션이 실제로 있는지는 확인하지 못했다 → 변경하지 않았다.

## 3. IndexNow (Naver)
- 공식 규격 재확인(Naver 가이드 indexnow-api-key / indexnow-request / indexnow-faq, indexnow.org): 엔드포인트
  `https://searchadvisor.naver.com/indexnow`, key 8~128자(hex·`-`), 루트 `{key}.txt`(UTF-8, key만), POST `host/key/keyLocation/urlList`,
  최대 10,000 URL, 200/202 성공 — **구현과 일치.**
- `INDEXNOW_KEY`: 128-bit 랜덤 hex 32자 생성 → Vercel `doran-coaching` 프로젝트 **Production만** 환경변수로 설정(타입 encrypted). 저장소에는 없음.
- 재배포(코드 변경 없음) 후 `/{key}.txt` 200 + body=key, 잘못된 key 404, 홈·robots·sitemap·RSS·매거진·지역 리프·route 응답 어디에도 key 노출 0건.
- baseline: 페이지 333개(매거진 50 + 상세 12 + 지역 허브 271) + 지역 리프 템플릿 15개. dry-run 후보 **0개**.
- 실제 전송: a4bf3e8에서 **내용이 실제로 바뀐** 3개(상세 `/english/certification`, 매거진 `hskk-speaking-prep`, 지역 리프 공덕동 HSKK과외)만 1회 → **HTTP 200**. 재전송 없음.

## 5. 정책안 (적용하지 않음)

판단 원칙: 검색 데이터가 없는 그룹을 noindex/삭제하지 않는다. "Google이 아직 크롤하지 않았다"는 것은 "가치가 낮아 색인에서 탈락했다"는 증거가 아니다.

| 대상 | 판단 | 근거 |
|---|---|---|
| 지역 리프 전체(15 keyword) | **KEEP (현상 유지) + DATA INSUFFICIENT** | Google 색인 1/97,905. 크롤 자체가 시작되지 않아 noindex·병합·삭제를 정당화할 데이터가 없다. |
| 과외 3종, 화상 3종 | **IMPROVE 후보** | 검색 데이터가 아니라 1차 감사의 내용 근거: 언어 간 유사도 62~76%로 키워드 중 가장 약하다. 단 문구 돌려쓰기 금지, 실제 차이가 있을 때만. |
| 시험 5종 | **KEEP** | examProfile로 가장 잘 구분됨(키워드 간 유사도 17~34%). |
| 영어회화/일본어회화/중국어회화/워홀일본어 | **KEEP** | 데이터 부족. |
| 동 허브 6,527 | **DATA INSUFFICIENT** | sitemap 제외 유지. 색인 0. |
| NOINDEX 후보 | **없음** | 근거 데이터 없음 |
| MERGE 후보 | **없음** | 〃 |
| DELETE 후보 | **없음** | 〃 |

### 지금 병목은 "중복 페이지"가 아니라 "Google 크롤 시작"이다
1. Google은 sitemap shard를 한 번도 읽지 않았다(1.3). 이것이 풀리기 전에는 리프 정책을 데이터로 판단할 수 없다.
2. 색인이 안 된 50개 매거진도 "발견됨 - 크롤 안 됨"이다. 이는 신규 사이트의 크롤 우선순위 문제로, 리프를 줄이는 것보다
   **핵심 URL(매거진 50 + 상세 12 + 허브)이 먼저 크롤·색인되게 하는 것**이 우선이다.
3. 따라서 다음 결정은 "Google이 shard를 읽기 시작한 뒤 2~4주 데이터"를 근거로 한다.

### 다음 결정에 필요한 데이터(수집 계획)
- GSC: sitemap shard 4개 처리 상태(읽음/발견 URL 수), 페이지 색인 보고서의 미색인 사유 분포(리프 기준), `/local/` 필터 실적.
- Naver Search Advisor: 사이트맵 수집 상태, 색인·수집 현황, 진단 오류.
- 기준: 리프 중 색인된 비율과 노출이 있는 keyword 그룹이 확인되면 그때 KEEP/IMPROVE/NOINDEX 후보를 재판정.
